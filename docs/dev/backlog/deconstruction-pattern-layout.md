# Problem

The "Deconstruction patterns (Java 21)" table in `docs/settings/java.md` — `DECONSTRUCTION_LIST_WRAP` (wrap-code int), `ALIGN_MULTILINE_DECONSTRUCTION_LIST_COMPONENTS`, `NEW_LINE_AFTER_LPAREN_IN_DECONSTRUCTION_PATTERN`, `RPAREN_ON_NEW_LINE_IN_DECONSTRUCTION_PATTERN`, `SPACE_WITHIN_DECONSTRUCTION_LIST`, `SPACE_BEFORE_DECONSTRUCTION_LIST` — is all ❌. Record patterns such as `case A(int x, String s) -> …` appear as pattern-matching `switch` labels; java-formatter formats switch bodies (shipped switch-formatting) but the label is echoed verbatim (`self.txt` on the `switch_label` in `crates/core/src/formatter.rs`), so the pattern list keeps its source layout and none of the six list-layout options apply — schemes setting them are only partially honoured (safely ignored, R7).

# Proposal

Parse the six options into `config::JavaStyle` via the `OPTIONS` registry in `crates/core/src/config.rs` (`DECONSTRUCTION_LIST_WRAP` as a wrap-code int reusing the `WrapStyle` mapping; the bools with their table defaults) and model record-pattern labels in `crates/core/src/formatter.rs` on the shipped record-component header template (`record_components` honours `RECORD_COMPONENTS_WRAP`, `ALIGN_MULTILINE_RECORDS`, `NEW_LINE_AFTER_LPAREN_IN_RECORD_HEADER`): wrap the deconstruction list per `DECONSTRUCTION_LIST_WRAP` with components aligned per `ALIGN_MULTILINE_DECONSTRUCTION_LIST_COMPONENTS`, put `(` / `)` on their own lines per the two paren options, and apply `SPACE_WITHIN_DECONSTRUCTION_LIST` (`case A( int x )`) and `SPACE_BEFORE_DECONSTRUCTION_LIST` (`case A (int x)`) around the rendered list. Any pattern shape outside the modelled form falls back to the verbatim echo (R4).

Docs touched: on delivery the implementation flips the six rows in `docs/settings/java.md` (❌ → ✅), updates the README formatting-behaviour notes for switch/pattern labels and the honoured-options table, adds a new requirement row to `docs/requirements.md`, and appends `docs/dev/changelog.md`.

# Decisions

- **The record header is the structural template.** The deconstruction list is a pattern-list analogue of the shipped record-component header: same wrap/alignment/paren-on-own-line mechanics, with the paren options read from this family's own defaults (both default `true` here) and `RPAREN_ON_NEW_LINE` carried by this request even though its record-header counterpart is not yet shipped.
- **Defaults.** Option entries carry the table's IntelliJ defaults; as with the recorded `RECORD_COMPONENTS_WRAP` divergence, `JavaStyle::default()` ships `DECONSTRUCTION_LIST_WRAP` = `DoNotWrap` so an absent option keeps today's single-line labels byte-identical (existing goldens stay green); the default-`true` align/paren options only matter once a wrap engages, and the spacing bools default `false` (today's compact `case A(int x)` form).
- **Modelled like records, verbatim otherwise.** Once modelled, pattern labels are laid out like other modelled constructs (records, switch); unmodelled patterns still echo verbatim (R4) and only whitespace/layout changes (R5).
- **One family, one request.** Unlisted switch/pattern options (e.g. other pattern forms) stay unimplemented and are ignored safely (R7).

# Acceptance criteria

- Golden fixture + test file per option under `crates/core/tests/options/`: an over-margin record pattern in a `case` label wraps per `DECONSTRUCTION_LIST_WRAP` codes `0`/`1`/`2`/`5`, with components aligned under `ALIGN_MULTILINE_DECONSTRUCTION_LIST_COMPONENTS`, `(` / `)` on their own lines under the two paren options (both `true`), and `SPACE_WITHIN_DECONSTRUCTION_LIST` / `SPACE_BEFORE_DECONSTRUCTION_LIST` = `true` fixtures; the absent-option compact form is asserted unchanged.
- Pattern labels that do not fit the modelled record-pattern shape still round-trip verbatim.
- Absent-option and default schemes keep today's output and the whole suite stays green (`cargo test`); the new goldens are idempotent.
- The six `docs/settings/java.md` rows flip to ✅ and the README switch/pattern notes are updated.

# Implementation plan

## Approach

**Configuration — `crates/core/src/config.rs`.** Add six fields to `JavaStyle` after the record block (`// --- deconstruction patterns (JavaCodeStyleSettings) ---`): `deconstruction_list_wrap: WrapStyle`, `align_multiline_deconstruction_list_components: bool`, `new_line_after_lparen_in_deconstruction_pattern: bool`, `rparen_on_new_line_in_deconstruction_pattern: bool`, `space_within_deconstruction_list: bool`, `space_before_deconstruction_list: bool`. `JavaStyle::default()` ships `deconstruction_list_wrap = DoNotWrap` (mirroring the recorded `RECORD_COMPONENTS_WRAP` divergence: the IntelliJ built-in default is `1`, but shipping `0` keeps an absent option byte-identical to today's single-line labels), `align = true`, both paren options `true`, and the two spacing bools `false`. The default-`true` align/paren options only matter once a wrap engages and the spacing bools default to today's compact `case A(int x)` form, so no existing output changes. Register six `OptionDef`s in the `OPTIONS` array between the records family and the imports entry — all `Section::JavaCodeStyle` (they live in the `<JavaCodeStyleSettings>` block alongside the record options), a new GUI group `"Deconstruction patterns"`, IntelliJ table defaults, and `get`/`set` closures over the new fields; the wrap entry reuses the existing `WrapStyle` int mapping (`0`/`1`/`2`/`5`). Registry defaults must equal the `JavaStyle::default()` values, since `parse_codestyle`/`serialize_codestyle` and the GUI (which renders whatever `OPTIONS` declares) depend on that — no other code needs to change.

**Rendering — `crates/core/src/formatter.rs`.** Today a record pattern in a switch is echoed verbatim because every `switch_label` is read with `self.txt`: in `switch_group` (~L1852-1865), `switch_rule` (~L1871-1907) and `switch_one_line` (~L1924-1987). Model exactly one shape — a `switch_label` whose single named child is a `record_pattern` node with a type child and a `record_pattern_body` list of pattern components. Any other label shape (a `type_pattern` such as `case String s`, several comma-separated patterns, unusual nesting, stray comments) returns `None` and the callers keep today's verbatim echo (R4), byte-identical. Begin by confirming the CST shape — the fields/children of `record_pattern` and `record_pattern_body`, and how `case` / `:` / `->` sit relative to the label node — with a one-off scratch parse of the intended fixture; the model keys off exactly what the grammar provides.

For the modelled shape, each component is rendered from its trimmed source text — the change only ever rewrites whitespace around the list, never text inside a component (R5). The layout mirrors the shipped `record_components` template (L642-691) with an independent rparen branch. Given the label start column `c`, the record type text and the parts: `open_col = c + len("case ") + len(type) + (space_before ? 1 : 0)`. The single-line text applies the spacing bools — `SPACE_BEFORE_DECONSTRUCTION_LIST` between type and `(`, `SPACE_WITHIN_DECONSTRUCTION_LIST` just inside the parens. Wrapping engages per `deconstruction_list_wrap` exactly as `record_components` decides (`DoNotWrap` never, `WrapAlways` always, `WrapIfLong`/`ChopDownIfLong` when `!fits(open_col, list_text)`), keeping `record_components`' single-component branch (with lparen off a lone component stays flat even under `WrapAlways`); codes `1` and `5` behave identically here because a component is atomic. When wrapping, the inner indent is `align_multiline_deconstruction_list_components ? open_col + 1 spaces : cont(indent)`; `NEW_LINE_AFTER_LPAREN_IN_DECONSTRUCTION_PATTERN` starts every component on its own line (the record newline-lparen branch), else the first component stays after `(`; `RPAREN_ON_NEW_LINE_IN_DECONSTRUCTION_PATTERN` closes with `)` alone at `ind(indent)` (which the record template does implicitly), else `)` hugs the last component (the record inline-lparen branch). Wire the layout into the three sites: `switch_group` and `switch_rule` lay the label out with wrap decisions taken against the label line's start column, and `switch_one_line` uses the single-line form (falling back to the verbatim label when the shape is not modelled), so an expression-position switch that cannot stay on one line falls back to the multi-line layout exactly as today.

**Tests.** Follow the hard conventions in `.agents/AGENTS.md`: one golden-pair test file per option at `crates/core/tests/options/<XML_OPTION>.rs`, wired into `tests/options.rs` alphabetically via `#[path = "options/<name>.rs"] mod <name>;`, fixtures in `crates/core/tests/java/<option>/` referenced with `include_str!("../java/<option>/…")`, `use super::common::*;`, no inline Java strings and only the `default_style`/`style`/`format`/`format_with` helpers. The family's fixtures share an over-margin arrow-rule switch (`switch (o) { case Point(int alphaComponent, int betaComponent, int gammaComponent) -> handle(); default -> {} }` in a method body — a statement-position switch always takes the multi-line layout), plus small single-line variants for the spacing options and unmodelled labels for the verbatim guard. Each option directory is self-contained (as the record-family directories already are).

**Docs.** `docs/settings/java.md` flips the six ❌ rows to ✅ and gains a `DECONSTRUCTION_LIST_WRAP` divergence note in the style of the Records one (table default `1`, shipped default `0`); `README.md` gains six honoured-option rows and an extension of the switch formatting-behaviour note; `docs/requirements.md` gains an `R16` requirement row plus a mention in the milestones paragraph; `docs/dev/changelog.md` is appended on delivery.
