# Problem

`INDENT_SIZE`, `CONTINUATION_INDENT_SIZE`, `TAB_SIZE` and `USE_TAB_CHARACTER` already ship (docs/settings/common.md "Indent options"; the latter two per R13's tab-stop output model), but every other row there is ❌: `SMART_TABS`, `LABEL_INDENT_SIZE`, `LABEL_INDENT_ABSOLUTE`, `USE_RELATIVE_INDENTS`, `KEEP_INDENTS_ON_EMPTY_LINES`, and the per-construct `DECLARATION_PARAMETER_INDENT` / `GENERIC_TYPE_PARAMETER_INDENT` / `CALL_PARAMETER_INDENT` / `CHAINED_CALL_INDENT` / `ARRAY_ELEMENT_INDENT` ints (each default `-1` = use `CONTINUATION_INDENT_SIZE`); `DO_NOT_INDENT_TOP_LEVEL_CLASS_MEMBERS` (common.md "Braces & indentation") is ❌ too.
Constructs therefore always use the base or continuation indent: a scheme's per-construct widths, `label:` indentation and tab/indent refinements are ignored (R7), so indentation fidelity is only partial.
The shipped tab-stop column arithmetic in formatter.rs (README `USE_TAB_CHARACTER` note) is where the tab-refining options must hook in.

# Proposal

Parse all eleven into `JavaStyle` via `OptionDef` entries in the `OPTIONS` registry in crates/core/src/config.rs — `DO_NOT_INDENT_TOP_LEVEL_CLASS_MEMBERS` in the JAVA `codeStyleSettings` block; the ten `<indentOptions>` rows (bools, `LABEL_INDENT_SIZE`, and the signed `*_INDENT` widths) in the indent-options section, with the IntelliJ defaults from the docs/settings table (absent → default) — and apply them in crates/core/src/formatter.rs at the constructs they govern: top-level class-member indentation, `label:` indentation, and the per-construct continuation-indent overrides, while `SMART_TABS` / `USE_RELATIVE_INDENTS` / `KEEP_INDENTS_ON_EMPTY_LINES` refine tab and blank-line indent behaviour on top of the shipped tab-stop model.

Docs touched: `docs/settings/common.md` "Braces & indentation" and "Indent options" marks flipped ❌→✅, the README honoured-options table and formatting-behaviour notes, `docs/requirements.md` (a new requirement row), and `docs/dev/changelog.md` on delivery.

# Decisions

1. **One family, one request.** Only the rows listed above ship; the `ALIGN_MULTILINE_*` alignment family and the switch/case indentation options (`INDENT_CASE_FROM_SWITCH`, `CASE_STATEMENT_ON_NEW_LINE`, `INDENT_BREAK_FROM_CASE`) have their own requests and stay unimplemented here and safely ignored (R7).
2. **Defaults.** Fields take the IntelliJ built-ins (`false`, `LABEL_INDENT_SIZE` `0`, `*_INDENT` `-1` = inherit), so default and absent schemes keep byte-identical current output and the existing goldens stay green.
3. **Semantics.** R5 holds — these options change only leading whitespace, tabs and empty lines, never tokens; R4 echoes unmodelled shapes verbatim. `SMART_TABS` / `USE_RELATIVE_INDENTS` interplay with the shipped tab-stop column arithmetic (formatter.rs): margin and wrap decisions keep logical columns so wrapping points do not shift (R13), and R6 is pinned by re-formatting the new goldens.
4. **Registry.** The five `*_INDENT` options default to `-1`, which the registry's unsigned `OptionValue::UInt` cannot represent — this family introduces a signed `OptionValue::Int` variant (`JavaStyle` fields hold `-1` = inherit) so parse(serialize(style)) == style for both explicit widths and `-1`; the bools and `LABEL_INDENT_SIZE` fit the existing variants.

# Acceptance criteria

- One `tests/options/<option>.rs` per option (fixtures under `tests/java/<option>/`): `DO_NOT_INDENT_TOP_LEVEL_CLASS_MEMBERS`, `SMART_TABS`, `LABEL_INDENT_SIZE`, `LABEL_INDENT_ABSOLUTE`, `USE_RELATIVE_INDENTS`, `KEEP_INDENTS_ON_EMPTY_LINES`, `DECLARATION_PARAMETER_INDENT`, `GENERIC_TYPE_PARAMETER_INDENT`, `CALL_PARAMETER_INDENT`, `CHAINED_CALL_INDENT`, `ARRAY_ELEMENT_INDENT` — bools asserted at `true`, each `*_INDENT` at an explicit width proving it overrides `CONTINUATION_INDENT_SIZE` for that construct kind only, labels under plain and absolute indents.
- Absent-option defaults (`-1` inherit, `false`, `0`) reproduce today's output byte-for-byte on the same fixtures; the whole suite stays green (`cargo test`).
- parse(serialize(style)) == style for the signed widths at explicit values and at `-1`; the tab-refinement goldens stay idempotent under the `USE_TAB_CHARACTER` tab-stop model (R13).
- docs/settings marks are flipped ❌→✅; the README, `docs/requirements.md` and `docs/dev/changelog.md` are updated with the implementation.

# Implementation plan

## Approach

**Scope note.** None of the eleven options overlap with sibling CRs: the switch/case indentation options (`INDENT_CASE_FROM_SWITCH`, `CASE_STATEMENT_ON_NEW_LINE`, `INDENT_BREAK_FROM_CASE`) and `SWITCH_EXPRESSIONS_WRAP` are owned by `switch-case-layout.md` and stay excluded here (Decision 1); the `ALIGN_MULTILINE_*` family is owned by `align-multiline-options.md` and also excluded. This CR touches only its own eleven options.

**Configuration (crates/core/src/config.rs).** Decision 4 requires a new signed variant: add `OptionValue::Int(i32)` to the enum (L203), a `get_int` helper on `OptionMap` (next to `get_u32`, L637), and an `Int` arm in both registry-driven decoders — `parse_codestyle`'s match on `def.default` (L712) and `serialize_codestyle`'s match on `value` (L745, emitting `n.to_string()`). Then add the eleven `JavaStyle` fields with their `Default` values (`smart_tabs`, `label_indent_absolute`, `use_relative_indents`, `keep_indents_on_empty_lines`, `do_not_indent_top_level_class_members` = `false`; `label_indent_size` = `0` (UInt); the five `*_indent` fields = `-1` (Int)) and the eleven `OptionDef` entries in `OPTIONS`: `DO_NOT_INDENT_TOP_LEVEL_CLASS_MEMBERS` in `Section::CodeStyleJava` (per the proposal), the other ten in `Section::IndentOptions`. Because the recorded defaults equal today's effective values (`-1` = inherit, `false`, `0`), absent-from-scheme options and the default style keep byte-identical output — no existing golden moves (AC2). The signed `-1` default serializes to nothing (skipped as equal to default) and parses back as `-1`, so `parse(serialize(style)) == style` holds for both explicit widths and `-1` by construction (AC3); per AGENTS.md no `parse_codestyle` tests are added, so this is verified by the shared-registry structure and a green suite.

**GUI (crates/gui/src/main.rs).** `option_row` (L133) matches `OptionValue` exhaustively (Bool/UInt/Wrap/Brace); the new `Int` variant breaks the build until an arm is added: a signed `egui::DragValue` (range `-1..=some max`) alongside the UInt arm (L141). No other code change is needed — the GUI is registry-driven.

**Rendering (crates/core/src/formatter.rs).** Five per-construct continuation widths: add a helper that resolves an explicit width (`>= 0`) to an indent string and otherwise falls back to today's exact string, then apply it at the constructs the options govern — `DECLARATION_PARAMETER_INDENT` in `formal_params`' declaration path (`is_call == false`, L1143; wrapped params currently at `ind(inner)`), `CALL_PARAMETER_INDENT` in the call path (`args_wrapped`, L2132, and `formal_params` `is_call == true`), `CHAINED_CALL_INDENT` in `fmt_chain` (L2223, currently `cont(indent)`), `ARRAY_ELEMENT_INDENT` in `array_init` (L2559, currently `ind(inner)`). The `-1` branch returns the current string, so defaults stay byte-identical (AC2) and an explicit width overrides that construct only (AC1). `GENERIC_TYPE_PARAMETER_INDENT` is wired through config/registry/GUI but is **inert in the renderer today**: generic parameter lists are always rendered flat via `flat_type_params` (L2684) and never wrap, so there is no wrapped-generic construct to override; the fixture documents parse/round-trip fidelity plus that the explicit width does not disturb any other construct, and the plan flags this until generic-parameter wrapping exists (out of scope). Labels: rework the `labeled_statement` arm in `stmt` (L1412) so the label line's indentation comes from `LABEL_INDENT_SIZE` / `LABEL_INDENT_ABSOLUTE` (absolute = `LABEL_INDENT_SIZE` from the margin; relative = statement indent + `LABEL_INDENT_SIZE`), accounting for the caller-prefixed statement indent; the default (`0`, non-absolute) reproduces today's output (AC1). `DO_NOT_INDENT_TOP_LEVEL_CLASS_MEMBERS` in `class_body` (L705): when set and the class is top-level (`indent == 0`, i.e. reached from `program` → `type_decl`, not nested), members indent at `ind(indent)` instead of `ind(indent + 1)`. `KEEP_INDENTS_ON_EMPTY_LINES` in `block` (L1258): the preserved blank line between statements emits the inner indent before the newline when set. `SMART_TABS` and `USE_RELATIVE_INDENTS` refine the shipped tab-stop model (R13) — `SMART_TABS` restricts tab emission to columns that land exactly on tab stops (alignment/continuation stays spaces), `USE_RELATIVE_INDENTS` selects how `cont`'s width is computed; both gate on `USE_TAB_CHARACTER`, both keep the default output byte-identical, and their exact IntelliJ semantics are pinned by goldens cross-checked against IntelliJ when available (the binary-expression precedent). All changes are whitespace-only (R5); unmodelled shapes keep the verbatim echo (R4); new goldens must be idempotent (R6).

**Tests.** Per AGENTS.md hard rules: eleven files under `crates/core/tests/options/` (`do_not_indent_top_level_class_members.rs`, `smart_tabs.rs`, `label_indent_size.rs`, `label_indent_absolute.rs`, `use_relative_indents.rs`, `keep_indents_on_empty_lines.rs`, `declaration_parameter_indent.rs`, `generic_type_parameter_indent.rs`, `call_parameter_indent.rs`, `chained_call_indent.rs`, `array_element_indent.rs`), wired into `tests/options.rs` via `#[path = "options/<name>.rs"] mod <name>;`, fixtures under `tests/java/<option>/` referenced by relative `include_str!`, each a golden pair asserted with `format_with` (or `format` for the default-style check). Bools asserted at `true`; each `*_INDENT` at an explicit width on a fixture that also contains the sibling constructs at their default widths (proving construct-only override); labels under plain (`LABEL_INDENT_SIZE` = 4) and absolute indents; tab-refinement goldens under `USE_TAB_CHARACTER`. Every file also asserts the absent-option default reproduces today's output, and each new golden is asserted idempotent by reformatting the golden and comparing it to itself (the `assert_idempotent` helper no longer exists — AGENTS removed it).

**Docs.** On delivery: flip the eleven `docs/settings/common.md` rows (ten in "Indent options", `DO_NOT_INDENT_TOP_LEVEL_CLASS_MEMBERS` in "Braces & indentation") from ❌ to ✅; add the eleven options to the README honoured-options table and extend the _Formatting behaviour notes_ (labels, per-construct widths, empty-line indents, smart/relative tab behaviour); add a requirement row to `docs/requirements.md` (the next free number — R16 unless `switch-case-layout` ships first, then R17) and touch the milestones paragraph; append a `docs/dev/changelog.md` entry (newest first).
